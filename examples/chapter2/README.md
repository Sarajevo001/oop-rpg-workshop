## team属性とコレクション管理

改善版では勇者・魔法使い・仲間スライム・敵スライムを単一の `characters` 配列に格納する。JavaScriptでは異なるクラスのインスタンスも同じ配列に格納でき、共通の `team` 属性で所属を判定して `filter()` で抽出できる。生存判定には `hp > 0` を併用する。表示も配列から生成し、個体ごとの表示処理を追加しない。

この変更は第2章の `solution/` から導入する。第1章の完成版と第2章の開始版は変更しない。第2章の完成版と第3章の開始版はHTML・JS同一。

## 後続改修の反映（2026-10-24）

第1章からカードの動的生成とターン別ログを引き継ぐ。第2章solutionでは異なるクラスのインスタンスを単一のcharacters配列で管理し、teamとhpを用いたfilterで敵味方・生存者を抽出する。キャラクターごとの表示用HTMLを増やさず、絵文字・名前・HPを配列から生成する。

## 改善例の説明順序（2026-10-24確定）

第2章の中心テーマは **「クラスの種類で分岐するのではなく、インスタンスのプロパティで違いを表現する」**。まず基本改善として `team` を導入し、`Slime.canAttack(target)` の個体判定・クラス列挙を `this.team !== target.team` に置き換える。ここで本章の学習目標を達成したことを明示する。

続いて **発展デモ（追加効果）** として、共通の `team` を利用した単一 `characters` 配列と `filter()` による敵味方・生存者の抽出、戦闘処理のループ化を紹介する。配列や `filter()` が `team` によって初めて使えるようになるわけではなく、共通属性を用意すると同じ基準で抽出しやすくなる、という説明に限定する。発展デモは追加演習ではなく講師による紹介とする。

`solution/` は発展デモまで反映した最終コードとし、第3章 `starter/` にそのまま引き継ぐ。フェーズ数は増やさない。表示用の `sprite` プロパティは第1章から存在する補助データであり、第2章の主題として説明しない。絵文字はこの規模では文字列として渡し、画像管理クラスは導入しない。
