# 第2章 追加要求の比較検証

## 固定条件
- 第1章の敵3体（スライム・ゴブリン・オーク）と共通ダメージ計算を保持する。
- 味方は勇者・僧侶・戦士から開始する。
- 味方追加、味方削除、HP回復、HP0の戦闘不能と行動不可、敵の反撃を比較する。
- 講座では受講者の途中完成を強制せず、共通コードに切り替えて進行する。

## ファイル
- `parallel-arrays/index.html`: 名前・HP・最大HP・攻撃・防御の5配列を添字で対応させる。
- `object-literal/index.html`: 各味方を1個のオブジェクトにまとめる。クラスは使わない。
- `class/index.html`: Characterクラスで生成と振る舞いを共通化する。

## 静的比較
| 追加要求 | 並列配列 | オブジェクト | クラス |
| --- | --- | --- | --- |
| 味方を1人追加 | 5配列にpush | 1オブジェクトをpush | new Characterをpush |
| 味方を1人削除 | 5配列にsplice | 1配列からsplice | 1配列からsplice |
| 戦闘不能者を除外 | hpsと同じ添字で名前等を参照 | actor.hpを参照 | actor.aliveを参照 |
| 回復処理 | hps/maxHpsを同じ添字で更新 | actorのプロパティを更新 | actor.healを呼ぶ |

**数値は「編集しなければならないコードの箇所数」ではなく、1人の追加・削除で同期するデータ構造の数**である。

## 検証上の注意
- 「5か所修正」は誤解を招く。上記は1回の操作で同期する配列の数であり、実際の編集箇所数ではない。
- オブジェクトだけで添字ずれ問題は解消する。クラスは一意の必須解ではなく、生成・振る舞いの共通化を示す。
- この3例は**技術比較用**であり、初心者が必ず並列配列を選ぶという意味ではない。
- 追加・削除操作は画面ボタンで再現できるが、現時点で実ブラウザの操作テストは未実施。
- 第1章の `solution` からの完全同一コード引継ぎは `continuity/start` で確認済み。この3例は追加要求を実装した後の比較スナップショットである。
- 味方が戦闘不能になっても敵からの反撃先は次の生存味方へ移る。戦闘不能者は行動できない。
- 戦闘不能者の復活は今回の回復仕様に含めない。
- 敵の反撃と味方の削除操作のゲームバランスは教材目的に合わせた仮仕様である。

## 次の判定
(1) PCブラウザで操作確認、(2) クラス化がオブジェクト化より改善する具体的な追加要求の妥当性確認、(3) 第3章へ同じRPGを継承する準備。
