# 第2章 接続検証（暫定）

**企画書v0.3の第2章に従う。章の確定ではなく、コード上の成立性確認。**

## 第1章からの接続
すべての例で第1章の改善成果である `calculateDamage` を引き継ぐ。ただし、**現在の第1章のsolutionと第2章のstartは同じファイルではない**。敵が3体から1体になっているなど、連続するアプリという合意条件をまだ満たしていない。これは検証用の局所サンプルであり、**正式な配布コードとして採用しない**。

## 比較対象
- `start/index.html`: 名前・HP・攻撃力・防御力を並列配列で保持。
- `object-literal/index.html`: 各キャラクターをオブジェクトリテラルにまとめる。
- `class/index.html`: 共通の初期化・攻撃・回復をクラスに持たせる。

## 追加仕様の仮説
1. 味方に戦士を追加する。
2. 味方の入れ替え・削除や、味方ごとの回復を実装する。
3. 同種のキャラクターを多数生成する要求を追加して、オブジェクトリテラルからクラスへの改善理由を検証する。

## 判断を保留していること
- 並列配列の煩雑さは、オブジェクトリテラルだけで大部分解消する。クラス導入の理由は**別途必要**。
- 「同種を多数生成する」だけでは `factory function` でも十分対応できる。クラスを唯一の正解としない。
- 受講者に並列配列を強制しない。初めからオブジェクトを使ったら正解として認める。
- 章の終わりには共通完成コードへ切り替えるという合意を維持する。
- 初心者の改修負担、講師の進行時間、前後章との実際の接続は未検証。

## 次に必要な検証
第1章の完成コードを第2章開始コードへ**機能を削らず**引き継ぐ形に改修し、全章を連続するRPGとして成立させる。現状は実装の選択肢を比較するための技術スパイク。
