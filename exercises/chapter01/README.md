# 第1章 検証セット（暫定）

## 目的
「同じ処理を何度も書かせるな！」を、動くコードで検証する。企画書の順序は「勇者対スライム → 敵を増やす → ダメージ計算の一斉変更」。

## ファイル
- `start/index.html`：勇者対スライムのみ。受講者への最初の配布候補。
- `naive/index.html`：ゴブリンとオークを追加し、敵別に攻撃処理を複製した比較用コード。**唯一の想定解ではない**。
- `solution/index.html`：共通攻撃処理と共通ダメージ計算を導入し、追加仕様を適用した例。

いずれも単体HTMLで、ブラウザで開くだけで動く想定。ビルド不要。

## 受講者への課題案（まだ未確定）
1. `start` から始め、ゴブリン（HP20、防御2）、オーク（HP28、防御3）を追加する。各敵を選んで攻撃できること。
2. 次の仕様変更を告げる。「ダメージは `max(1, 攻撃力 - 防御力 × 2)` とする」。すべての敵に適用する。

## 比較するポイント
- `naive` では、ダメージ計算式を**3か所**変更する必要がある。
- `solution` では、`calculateDamage` の**1か所**に変更が集中する。
- ただし、`solution` は計算の共通化に加え、攻撃処理の共通化も行っている。変更箇所の比較は**計算式に限定**して数える。
- `naive` は仕様変更**前**、`solution` は仕様変更**後**の状態。単純なダメージ数値の一致比較には使わない。

## 未検証・懸念
- 現在は静的なコード比較のみ。受講者が実際に重複実装を選ぶか、十分な「イラッと」が発生するかは未検証。
- 3か所の修正だけでは負担が弱い可能性がある。数を増やす前に、講座の時間と初心者の認知負荷を検討する。
- 初回改修の時点で汎用関数を作る受講者は正解として認める。
- 次章へ渡す共通ベースの内容は、章間整合性の検証後に確定する。
