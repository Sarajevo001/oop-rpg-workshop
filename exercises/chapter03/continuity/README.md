# 第3章 技術検証：行動の追加

## 企画書 v0.3 との関係
- 第2章のクラス版を共通ベースの**一例**として採用。クラス以外の妥当な解決を不正解にしない。
- 同じRPGの味方3人、敵3体、ダメージ計算、味方の追加・削除、回復、敵の反撃を維持する。
- 第3章の仮説は「新しい行動が増えるたび、既存の分岐を書き換える負担」。関数渡しが唯一の正解という説明はしない。

## ファイル
- `start/index.html`: 第2章の `continuity/compare/class/index.html` と完全同一の内容。
- `switch/index.html`: 行動名の文字列を `performAction` 内の if/else で分岐。通常攻撃、炎、氷、回復を追加。
- `callback/index.html`: 行動を関数として `performAction` に渡す。行動別の処理を外へ分離。

## 比較と限界
- 分岐版では新行動の追加時に `performAction` の条件分岐を変更する。
- 関数渡し版では新行動の関数を追加して呼び出し元から渡せば、`performAction` 本体は変更しない。
- **両版とも**UIに行動を追加するための変更は必要。今回のUIは行動名リストをハードコードしているため、行動定義の追加だけで自動的にボタンが増えるわけではない。
- callback版の `actions` はオブジェクトであり、関数渡しとオブジェクトを対立する選択肢として扱わない。
- 関数渡しはオブジェクト指向に固有の発明ではない。
- 第3章の最初の改修をどの状態から始めるか、追加行動の数・負担・説明時間は未確定。
